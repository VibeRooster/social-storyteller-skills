# Required structure

## 1. Title header

- `# <Series name> — <subtitle> (draft vN, HEIT)`
- One-line context (hub URL if any, audience, week).
- Format legend: `Format: Beat | VO | s | Type (CAM = on-camera, SCR = screen demo, BRD = board/graphic) | Screen / visual.` Add `[TIM: …] = gap only Tim can fill` when needed.
- Standing production notes if relevant (CTA line, end-card tiles, mic mode).

## 2. Index table

Columns fit the series, for example:

- Gallery week: `# | Pick | Creator | Score | Phase | URL`
- Teach series: `# | Piece | Focus | Metaphor`

## 3. Overview (~50–55s) — WHY …

- Emphasize WHY (rubric, decoder, frame), not a full how-to of every piece.
- `On-screen hook (0–3s): "…"`
- Optional audience tagline for enterprise / ops Reels.
- HEIT table (Overview may use multiple Illustrate rows to preview each piece in one beat each).
- `Alt hooks:` one or two backups after the table.

## 4. Detail sections `## 1/5` … `## 5/5`

Or ★ honorable mention when the series uses it. Each detail section:

- Title with score / phase / creator or metaphor as fits; target duration in the heading (~40–50s).
- `Spoken hook:` full first line said on camera.
- `On-screen hook:` short caption variant (often tighter than spoken).
- HEIT table.
- Optional caption-only team question or `[TIM: …]` notes under the table.

## 5. Open questions

Numbered list of decisions only the author can make (alt endings, which framework a test returned, Graphics vs live board, CTA / gallery link, and similar).
